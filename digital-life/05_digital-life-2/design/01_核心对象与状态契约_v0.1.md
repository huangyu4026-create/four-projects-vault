# 数字生命2.0｜核心对象与状态契约｜v0.1

本文件定义逻辑对象，不预先决定SQLite表名。实施时优先复用现有`source_documents`、`evidence_items`、`fact_assertions`、`relations`、`psychological_patterns`、`query_runs`与`readout_runs`，只有真实闭环缺少承载对象时才新增表。

## 1. MemoryUnit｜活记忆单元

一条活记忆不是原文摘要，而是可回到原文、具有时间和修订史的最小记忆对象。

最低字段：

- `memory_id`
- `statement`
- `statement_type`：事实、经验概括、本人原话、系统解释、待证假说
- `event_time`：事情发生时间
- `formed_time`：记忆对象形成时间
- `valid_from / valid_to`
- `source_anchors`
- `supporting_fact_ids`
- `counterevidence_ids`
- `confidence_state`
- `ownership_state`
- `sensitivity_level`
- `access_scope`
- `current_version_id`

状态：

`CANDIDATE → USER_CONFIRMED / HELD / REJECTED → REVISED / SUPERSEDED / WITHDRAWN`

禁止：

- 无来源直接成为确认记忆；
- 用AI摘要覆盖原文；
- 把今天的理解倒写成当年的想法；
- 删除旧版本使变化不可见。

## 2. MemoryVersion｜记忆版本

记录一条记忆为什么改变，而不只保存“最新值”。

最低字段：

- `version_id`
- `memory_id`
- `previous_version_id`
- `statement_snapshot`
- `change_type`
- `change_reason`
- `trigger_source`
- `changed_by`
- `created_at`

变化类型至少包括：新增证据、用户纠正、反证出现、时期失效、范围缩小、解释替换、主动撤回。

## 3. ModelHypothesis｜个人模型假说

个人模型只表达“在什么材料和范围内，目前较合理的解释是什么”，不表达人的本质。

最低字段：

- `hypothesis_id`
- `claim`
- `domain`
- `applicable_period`
- `applicable_context`
- `supporting_memory_ids`
- `counter_memory_ids`
- `strongest_counterargument`
- `alternative_explanations`
- `failure_conditions`
- `evidence_sufficiency`
- `ownership_state`
- `version`

状态：

`SYSTEM_CANDIDATE / USER_CONFIRMED_AS_SELF_UNDERSTANDING / HELD / CONTESTED / REVISED / RETIRED`

`USER_CONFIRMED_AS_SELF_UNDERSTANDING`不等于P05中的个人生命立场。若需要成为立场，必须由P05独立接收、重新判断并获得用户确认。

## 3A. GlobalComputerWorkJudgment｜电脑全局工作判断

用于概括一个时期内煜在本地各工程中正在做什么、承担什么角色、参与程度和连续状态。它是人物画像和阶段性自我概括的工作观察输入，不是人格假说，也不是生命立场。

最低字段：

- `judgment_id`
- `period_start / period_end`
- `generated_at`
- `project_rows`：工程ID、名称、类型、正在做什么、角色、参与程度、频度、连续状态
- `evidence_anchors`
- `uncertainties`
- `user_corrections`
- `previous_judgment_id`

状态：

`SYSTEM_PERIODIC_JUDGMENT → USER_CORRECTED / SUPERSEDED`

第一版采用文件快照承载，不新增SQLite表。只有多期稳定重复、证据充分且经过反证检查的内容，才可作为`ModelHypothesis`的证据；单期判断不得直接写成人格结论。

## 3B. PersonalHealthStateObservation｜个人健康与身体状态观察

用于保存和概括煜本人已经表达或已有资料支持的身体状态与健康事实。它是人物画像的健康观察输入，不是医学诊断，也不等同于“身体与审美”模型假说。

最低字段：

- `observation_id`
- `period_start / period_end`
- `generated_at`
- `self_reports`
- `daily_life_records`
- `medical_records`
- `system_summary`
- `source_anchors`
- `data_freshness`
- `uncertainties`
- `safety_boundary`
- `user_corrections`
- `previous_observation_id`

状态：

`MATERIAL_PRESENT / CURRENT_OBSERVATION / STALE_NEEDS_REFRESH / USER_CORRECTED / SUPERSEDED`

第一版采用文件快照承载，不新增SQLite表。关键词和语义标签只用于召回；必须核对人物主体、时间和语义，不能把他人身体、身体审美或康养项目自动算作煜的健康状态。

## 4. CalibrationCase｜真人校准题

用于检验数字生命是否真的理解煜，而不是只会生成相似文风。

最低字段：

- `case_id`
- `question`
- `question_domain`
- `system_answer_before_user_answer`
- `retrieved_context_manifest`
- `user_answer_raw`
- `comparison_dimensions`
- `difference_summary`
- `error_class`
- `affected_memory_ids`
- `affected_hypothesis_ids`
- `revision_decision`

误差至少区分：

- 材料不足；
- 召回错误；
- 旧阶段误当现在；
- AI过度推断；
- 用户本人发生变化；
- 问题口径不清；
- 系统答对但证据路径错误。

## 5. ContextPackage｜最小上下文包

跨工程调用的唯一正式载体。接收方不得直接读取全库。

最低字段：

- `package_id`
- `requester`
- `purpose`
- `question`
- `allowed_domains`
- `excluded_sensitive_domains`
- `memory_ids`
- `source_anchors`
- `model_hypotheses`
- `uncertainties`
- `expires_at`
- `revocable`
- `package_hash`

## 6. AccessReceipt｜访问与接收回执

最低字段：

- 谁请求；
- 为什么请求；
- 实际读取了什么；
- 拒绝了什么；
- 返回了什么；
- 接收方是否正式使用；
- 是否写回目标工程；
- 用户是否撤回授权。

没有目标工程接收回执，只能标记`DELIVERED_NOT_ADOPTED`，不得宣称已经完成跨工程对接。

## 7. ObservationStream｜外部观察流

属于后期可选对象，第一版不创建。

原则：

- 默认关闭；
- 采集前明确目的和期限；
- 优先日级汇总，不采集不必要的窗口标题和正文；
- 原始观察不能直接生成性格或心理结论；
- 可以暂停、导出和删除；
- 任何健康相关推论必须降级为非诊断观察。
