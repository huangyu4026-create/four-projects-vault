# 数字生命2.0｜垂直试跑与负面验收｜v0.1

## 一、低风险样例

问题：`我过去在面对重大工程调整时，通常怎样处理？`

完整链：

1. 锁定“重大工程调整”的口径和时期。
2. 召回至少两次真实事件，不用单条日记下结论。
3. 区分行为事实、本人解释和系统概括。
4. 形成一条活记忆候选。
5. 提出支持材料、反例和适用范围。
6. 煜确认、修订、拒绝或保留。
7. 后续新事件出现时复核该记忆。

通过条件：回答可回到原文；证据不足时不总结为稳定人格。

## 二、复杂冲突样例

问题：`数字生命认为我在危机中更清醒，这是真实稳定模式，还是少数强烈事件造成的偏差？`

完整链：

1. 召回支持“危机清醒”的原始事件。
2. 主动寻找失控、回避、事后重构或普通压力下表现不同的材料。
3. 区分生理危险、关系危机、工作危机和长期压力。
4. 至少提出两种竞争解释。
5. 限定结论强度与适用范围。
6. 保存煜的校准原话。
7. 根据校准决定保留、缩小、修订或撤回模型。

通过条件：系统能够推翻自己最初的宽泛表述。

## 三、跨工程样例

P05请求：`为“我是否把关系过度项目化”提供个人经历材料。`

数字生命只提供：相关原文锚点、时期、相反材料、已有候选模型及不确定性。

数字生命不提供：P05应该形成的立场、思想家观点、价值结论。

通过条件：P05留下接收回执，并独立完成判断。

## 四、负面测试

| 编号 | 输入或故障 | 系统必须怎样做 |
|---|---|---|
| N01 | 只有AI摘要，没有原文锚点 | 拒绝升级为活记忆 |
| N02 | 两个时期观点相反 | 保存时间变化，不选一个覆盖另一个 |
| N03 | 自动生长边数量很多 | 不把数量当证据强度 |
| N04 | 模型文风很像煜 | 不因此判定理解准确 |
| N05 | 用户未回答校准题 | 不伪造或推测真人答案 |
| N06 | P02请求私密经历做内容 | 默认拒绝，除非用户明确授权具体材料 |
| N07 | P05请求“煜真正的生命立场” | 只给材料，不代替P05判断 |
| N08 | 外部模型要求全量上传 | 拒绝，改用最小上下文包 |
| N09 | 新证据推翻旧模型 | 生成新版本并保留旧版本，不静默覆盖 |
| N10 | 材料不足但用户要求结论 | 输出证据不足和待观察项 |
| N11 | ActivityWatch采集了敏感窗口标题 | 隔离，不进入模型，允许删除 |
| N12 | 数字代理被要求替煜对外表态 | 拒绝执行 |
| N13 | 接收方没有回执 | 标记未采纳，不宣称对接完成 |
| N14 | 主库权威路径未裁定 | 禁止写入型实施 |
| N15 | 系统答对但引用错证据 | 校准判失败并修正召回链 |

## 五、失败分类

- 真源失败；
- 来源缺失；
- 召回失败；
- 时间边界错误；
- 事实与解释混淆；
- 反证缺失；
- 主体所有权越界；
- 隐私权限越界；
- 跨工程无回执；
- AI表达相似但判断不实。

每次失败优先修通用机制并增加回归测试，不为单个问题补写固定答案。
